**最慢的两个环节（按对体验的影响排序）：**

1. **滚动期的卡片宿主重建**。10.7 秒里主循环只 tick 了 41 次（中位间隔 **257.96ms**、p99 **444.71ms**、最长 562.5ms），同期 `card_host_create` **644 次**（≈60 次/秒）。最大的几个主循环空档与卡片创建突发落在同一窗口（562ms 内 51 张、490ms 内 61 张），推算单张宿主重建约 **8–10ms**。同期 `gallery_apply`、`selection_view_commit` 均为 **0**，`scroll_bounds` 142 次 —— 说明滚动时**没有重新查询、没有换数据集**，代价全在视图侧。
2. **首屏的缩略图生成**。3.3 秒里，读库+打开约 0.93s（冷）/0.70s（热）、`query_and_sort` 433–450ms、`gallery_snapshot_complete` 71–74ms，**剩余约 1.8s 是预览管线把可见区缩略图排空的时间**；`card_host_create` 首屏只有 7 次、`gallery_apply` 10–11 次，说明首屏不是宿主问题而是**解码/取图问题**。

**原因推断（有代码位置，未改）：**

- 卡片复用只复用了容器，没复用 SwiftUI 宿主：`NativeMaterialGallery.swift:486-508` 的 `configure` 在 `representedID` 变化时先 `hosting?.removeFromSuperview(); hosting = nil`，再 `NSHostingView(rootView: card)` 新建并记 `card_host_create`；`prepareForReuse → discardPresentation`（`:509-518`）同样把 hosting 置 nil。所以每个滚进可见区的卡片都要重建一次视图层级并走一次 SwiftUI 首帧，而这不是「复用」。
- 卡片重绑先把图清空：`MaterialThumbnailView.swift:78-84` `reloadThumbnail()` 里 `image = nil`，两次尝试之间还可能 `sleep(180ms)`。这既造成滚动时的空白闪烁，也把等待时间推到主循环间隔的量级。
- 画廊缩略图能不能落盘，取决于一个很紧的闸门：卡片请求的边长是 `galleryPreviewMaximumDimension = min(512, previewMaximumDimension)`（`UnifiedLibraryWorkspace.swift:1080-1084`、`LibrarySession.swift:29`），刚好落在磁盘写分支的门槛上；而写盘只在 `PreviewImagePipeline.swift:254-265` 的 `!fullResolution && target >= 512 && !acceptsDisk` 且**非阻塞**抢到 `diskWriteGate`（值 1，`:34`）时才发生，抢不到就静默跳过（注释原话「At most one write retains an image; extra cache writes are simply skipped」）。快速滚动时每秒新增几十张，单飞门几乎一直被占；加上冷启动口径本身会先清 `<QA根>/PreviewCache`，整个测量跑下来隔离副本只落了 **15 个文件**（`Thumbnails` 9 + `ScreenPreviews` 6）。内存层是 `NSCache` 480 项/64MB（`PreviewImagePipeline.swift:95-98`），键里含 `g:<generation>`，切库/卷事件即 `removeAllObjects`，进程重启全失效。
- 筛选与切文件夹的 0.75–1.2s 里，`query_and_sort` 占 240–455ms、`gallery_snapshot_complete` 占 35–44ms，其余是卡片重建（14–18 次宿主）+ 状态轮询粒度（单次 CLI `status` 约 134ms）。所以这几项**不是纯 SQL 慢**，而是「查询 + 视图重建 + 排空等待」的合计。

## 1. 测法（可复跑）

```bash

python3 证据_生产库.py --out 证据_生产库测前.json     # 测前只读快照

python3 证据_生产库.py --out 证据_生产库测后.json

# 4) 复现辅助工具（脚本自动编译，也可手动）
swiftc -O 界面驱动.swift -o bin/界面驱动
swiftc -O 帧率探针.swift -o bin/帧率探针

```

测量口径要点：

- **只有滚动帧率必须前台**：滚轮事件要命中最前窗口且光标落在图库区。其余三项走 `ASSETFRAME_QA_DATA_ROOT` 隔离实例 + CLI/辅助功能，后台即可完成，不会打断办公。
- 滚动参数：1440×900 窗口、400 个滚轮事件 × `-80px`（负值才是向下）、间隔 25ms、共 32000px；采集宽度 1280、请求 60fps。滚动点按窗口比例 `(0.58, 0.78)` 定位，避开工具条和左侧「项目分类」面板。
- 探针自校准：同一探针跑已知 60Hz 的 `校准动画` 窗口，拿到 **delivered 56.42fps / 中位间隔 17.32ms** —— 说明探针上限足够高，实测 App 只有 19fps 投递、12fps 内容变化不是采集造成的。
- 帧率两个口径都记：`avg_fps` = 内容真的变化的帧/秒；`delivered_fps` = 采集到的帧/秒（窗口实际被刷新的节奏）。
- CLI 侧耗时（大图/筛选）由 `measure` 的回执 + App 内 query/media/queue 状态判定，`completionScope` 明写 `excludes screen FPS and pixel-presentation timing`；单次 `status` 往返约 134ms，所以这些数字有 **±0.15s** 的测量分辨率。
- 每轮前 `reset_browse` 把隔离副本的 browse 状态归一化（scope=all、搜索清空、kinds=[图片]、scrollY=0），冷启动还会清 `<QA根>/PreviewCache`，保证不是拿上一次缓存蒙分。

## 3. 口径差异必须讲清楚

- **本次首屏/滚动是「磁盘缩略图基本为空」的口径。** 隔离副本只带库、不带缓存，冷启动前还会清 `PreviewCache`；而生产机器上同一个库已经有 **2416 个 512px 缩略图**（`/Volumes/SSD-1TB/Codex创作媒体库/99_可重建缓存/AssetFrame/9181878D-…/v1/Thumbnails`，缓存目录共 883MB）。也就是说用户真实首屏有一部分卡片能走「读 512 PNG」而不是「读原图解码」，**本次四项数字对首屏/滚动偏悲观**；`card_host_create` 那条与缓存无关，属于确定性开销。
- 缓存 key 只用**路径字符串**（`SSDPreviewCache.thumbnailKey`：`SHA256(路径|size|mtime|512)`，不解析符号链接），镜像路径与真实路径是两个 key。所以「把生产缓存复制进隔离根」并不能直接复用，要先按镜像路径重算 key 改名；这一步本轮没做。
- 素材是符号链接指向 `/Volumes/SSD-1TB`（外置 SSD）上的原文件，与原机一致的读盘路径；`/tmp` 只放库副本与状态文件（整个 QA 根 17MB）。
- 未测的口径：>1 万张的图库、多库切换、`全屏预览 4K 原图`、以及带充分磁盘缓存的热身首屏。

## 5. brand 自测断言修复（唯一代码改动）

`macos/SelfTests/MaterialClassificationSelfTest.swift:29` 原本是：

```swift
precondition(scoped.allSatisfy { !$0.canonical.isEmpty && !$0.aliases.isEmpty }, "词条缺少标准词或别名：\(dimension.id)")
```

实跑崩溃：`main/MaterialClassificationSelfTest.swift:29: Precondition failed: 词条缺少标准词或别名：brand`（进程 SIGTRAP，退出码 133）。

原因在词表本身：`ClassificationVocabulary.swift:69` 的品牌词 `茶盈航` 写成 `aliases: []`，`brand` 维度里这类专有名词只有一种写法是刻意的；匹配逻辑走 `[canonical] + aliases`，标准词自身就能命中，空别名不影响功能。要求每条词都必须有别名，是在断言里发明了一条词表没有的规则。

所以**改断言、不改词表**，并把要保证的东西写准（标准词非空 + 别名里不得混入空串）：

```swift
precondition(scoped.allSatisfy { term in
    !term.canonical.isEmpty && term.aliases.allSatisfy { alias in !alias.isEmpty }
}, "词条标准词为空或别名里有空串：\(dimension.id)")
```

实跑验证（等价编译清单，见第 6 节）：

- 用 `git show HEAD` 的旧断言原样编译运行 → **崩溃在第 29 行**，日志 `/tmp/cls-head.log`。
- 用当前工作区版本编译运行 → `MaterialClassificationSelfTest passed: vocabulary, single/multi, filter, search, legacy decoding, undo and database round trip`，退出码 0。
