## 1. 目标与边界（承接方案一）

已确定的分工：

- **备注只做说明**：备注（`note`）是给人看的自由文本，不承担分类，不参与筛选统计，AI 不自动写备注。
- **分类走结构化字段**：分类值来自本词表的受控词条；备注、分类两套数据分开存储，互不覆盖。
- **词表是「可选项清单 + 默认推荐」**，不是强制枚举：允许项目扩展自定义词，但要标状态与来源。

本轮只做词表；命名、AI 识别、兜底归组是后续三步（见第 6 节）。

## 3. 方法

1. **收集**：按文件名含「提示词 / prompt」检索，取 `.md / .txt / .json`；JSON 只取 `prompt` 字段；同时并入素材库索引里的提示词文档。
2. **去噪**：排除修改记录、学习与模板、提示词模板说明、待判定收件箱等非实际提示词文档。
3. **去重**：正文去空白后按 SHA-1 去重，保留一份。
4. **短语提取**：按标点切分子句，提取 2–8 字连续中文 n-gram 与英文 token；统计「文档频次」（同一文档只计一次），用最长短语过滤去掉被更长短语覆盖的碎片（如「光影氛」被「光影氛围」覆盖）。
5. **人工归类**：按 11 个维度人工筛选、合并同义词、写说明；剔除语料中无证据或证据不足的词。
6. **计数**：对最终词条按别名重新匹配语料，得到提示词文件数、出现次数、分域分布；项目实体再统计素材文件名证据数。
7. **复核**：`词表复核.py` 可按来源清单重算，防止词表与语料漂移。

计数口径说明：

- **提示词文件数**：包含该词（任一别名）的去重文档数，反映「有多少份提示词用到它」；比出现次数更抗模板重复。
- **出现次数**：原始出现次数，受模板/重复段落影响，只作参考。
- **文件名证据数**：仅项目实体统计，`originalFilename + name` 中出现该词的素材数；同一实体可能被多个词条重叠计数（如「红茶」是「海南红茶」的子串）。

### 4.3 两个域的差异

- **古装短剧域**：人物/服装/姿态/机位/宫格/四视图/头身比/青石/麻布/官服/布鞋/旧衣等证据强；大量提示词是「资产设定图 + 分镜图」，强调身份一致、构图规格、禁止现代物品。

- 语料零证据：民国、跪姿、山野、雨天、顺光、烛光、油画、8K、穿帮、多余手指、错字等，未纳入 v0.1。

## 5. 词云筛选器怎么用

双击打开 `词云筛选器.html`（纯本地文件，不联网）：

1. 顶部按**维度**和**状态**筛选，搜索框可按词或同义词过滤。
2. 字越大 = 提示词文件数越多；颜色代表维度；悬停看计数、别名与说明。
3. 点击词条加入/移出右侧「我的词表」，选择会存在浏览器本地。
4. 「勾选全部推荐」快速得到 v0.2 基线；「勾选当前筛选」按维度成批选。
5. 导出 CSV/JSON 即为你的 v0.2 候选；也可以复制文本直接贴回对话。

## 6. 四步流程设计（词表之后的落地路径）

### 第 1 步：词表（本轮）

- 输入：提示词语料 + 人工判断。
- 输出：本目录 v0.1；用户筛词后冻结 v0.2。
- 验收：用户实际点选过一轮，状态与别名确认；不把「推荐」当强制值。

### 第 2 步：导入后按分类 + 相似文件命名

- 输入：新导入图片的分类（资产类型/主体/视角/用途）+ 同目录/相似文件的命名习惯。
- 输出：建议文件名，格式示意 `类型_主体_视角_用途_版本`（例：`人物_许长山_正面半身_已确认_v02`），最终以 `命名规则_草案_v0.1.md` 的统计为准。
- 规则：先匹配同目录/相似文件命名模式；重名时加序号或短指纹；分类不全时留空而不是编造；无法判断时用第 4 步兜底名。
- 验收：100 条真实样本抽样可读、不重名、可回溯到原始文件名。

### 第 2 步的实测依据（命名分析已完成）

`命名规则_草案_v0.1.md` + `命名规则_数据.json` 已对 18,480 条素材（其中图片 3,111 张）做完只读命名分析，结论与词表的对应关系：

- **事实标准是 `_`**（81.5%），版本 `vNN` 放在最后（37.3% 的图片含版本，83.4% 在末段），状态词在版本前；日期/时间戳只占 2.7%，不放进标准模板。
- **真正的问题不是微信图片（严格口径 3.3%），而是机器导出名**：把 `slide_/frame_/contact_/final_/image` 等算入后占 35.4%；完全不含中文的图片名 44.8%。因此自动命名必须依赖「分类 + 主体」，只做字符清洗没有价值。
- **重名严重**：同库同名 413 组 / 多余 959 条（30.8%），其中同名不同内容 223 组；内容指纹重复 450 组 / 722 条。**命名前必须查 `contentFingerprint`，不能只按文件名判重。**
- **两库风格差异大**：古代种田结构化命名 70.9%，香万家木兰只有 28.0%；香万家 `/Volumes` 客户储存来源 84.3% 是原始/机器名。自动命名应先看同目录多数风格，再决定是否套模板。
- **模板**：`[项目_]{类型}_{主体}[_{视角或变体}][_{用途}]_{状态}_v{NN}`；字段来源直接映射词表维度——类型=`asset_type`、主体=`entity`、视角=`shot`、用途=`usage`、画质=`quality`；状态只允许「候选 / 已确认 / 历史停用」，**不得从文件名推断「已确认」**。
- **冲突与兜底**：重名先查内容指纹 → 同组合版本 `vNN` +1 → 仍冲突加 `_h{8位指纹}`；判断不了用 `待分类_YYYYMMDD_三位序号`，`待分类/待补充` 是占位符不是分类值。

### 第 3 步：AI 识别（用户提供 AI 后再接）

- 输入：图片（或缩略图）+ 词表（只给受控选项）。
- 输出：分类建议 + 置信度 + 依据（可选多个）。
- 规则：**只能从词表取值**；低置信度不落库；AI 不写备注；人工确认后才写入分类字段；保留原始建议记录以便复盘。
- 验收：真实图片集上的建议可复核；错误可一键拒绝；不产生备注污染。

### 第 4 步：兜底归组 + 人工判断

- 输入：AI 判断不了或置信度低的图片。
- 输出：归入「待判定组」，按相似度（目录、尺寸/画幅、批次、文件名近似、视觉相似）自动分组。
- 规则：组内一次人工确认可带动整组；每组保留来源与依据；确认前不写正式分类；允许拆分/合并组。
- 验收：待判定组的数量、分组质量和人工处理速度有记录。

## 7. 已知限制

1. **语料偏向**：古装短剧（249 份）明显多于茶商业（170 份），且大量提示词是同一项目的模板变体；频次反映「这个项目怎么写」，不完全等于「全公司通用」。
2. **计数污染**：如「背景」含「背景音乐」、「参考/候选/已确认」是流程词不是内容词、「现代」含否定语境；词条说明里已标注，仍建议结合上下文。
3. **同义词合并靠人工判断**：例如「国漫 / 3D 国漫 / CG / 3D」合并为一个词，可能损失项目差别。
4. **实体词重叠**：多个实体互为子串（红茶/海南红茶）会重复计数；实体仅代表文件名与提示词出现，不代表图片里一定有。
5. **未做语义聚类**：同类不同说法可能仍是两个词（如「棚光 / 摄影棚光」），需要后续同义词表维护。
6. **未验证真实流程**：词表尚未接入 App 的分类字段、批量入口和 AI 链路；命名规则、AI 识别、兜底归组都还只是设计，不是已实现功能。
7. **隐私边界**：语料全部在本机读取，未上传；`数据来源清单.csv` 含本机绝对路径，若对外分享需先脱敏。
