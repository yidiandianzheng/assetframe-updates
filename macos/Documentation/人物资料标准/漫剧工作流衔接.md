# 漫剧资料与资产调用闭环

本规范用于 V261017.2 隔离候选；构建、测试、界面验证及安装状态以 `ProductValidation/20261017_资产工作流整合/README.md` 为准。

## 日常操作

Codex 完成创作并留下标准记录 → 人物库刷新 → 查看项目资料整理概览 → 核对旧资料候选和冲突 → 取用具体素材与提示词 → 回到外部 AI 平台制作。

人物库登记项目后，刷新会直接关联身份一致且唯一的标准人物 MD，核验标准确认记录，更新软件读取缓存。人物正文不因刷新而写回。原始素材保持原路径；已核验但尚未入库的确认文件，可在人物详情集中建立原位索引。

项目资料整理先显示新增、变化、未读到、标准记录、人物与问题概览，文件清单可展开。按人物接口 ID、标准身份、已有索引和明确链接归组；姓名匹配仅给建议。明确链接可读取历史目录，历史属性不因此失效。缺失、超限或不可读会提示不完整，旧登记不会被清空。

## 整理与增量刷新

- 软件索引缓存位于资源库的 `project-intake.json`，保存读取指纹与 AI 候选，不保存另一份正式人设。
- 候选缓存绑定项目、人物、目标姓名、来源内容指纹、导航内容指纹和整理规则版本。同一来源换人物不能复用；入口或索引变化后旧候选失效。
- DeepSeek 使用当前人物整理任务配置的快速模型。用户启动整理后，软件按每批 30 份／160 KB 顺序处理，仅发送选中的旧资料。标准记录不发送；已完成批次保留，失败可以重试。
- 返回候选必须有原文逐字依据。集中预览时仅补空字段，冲突保留当前值。保存前再次检查来源，草稿不会因失败丢弃。
- 已读取、已整理候选、已确认、已用于制作分别显示。模型整理不能产生用户确认。

## 确认继承与当前状态

标准确认记录通过项目 ID、人物 ID、档案路径和真实文件 SHA-256 核验后直接展示。原始提示词和复用模板分开。已有 MD 中的停用或候选状态优先于旧确认事实；默认用途不会被旧记录重设。文件被覆盖后，该确认暂不可选用。

人物默认用途仍保存在原人物 MD。项目资产界面为人物设置默认时，预览并写回该档案，同时在项目资产记录留下事件；涉及多文件保存时明确报告部分成功。场景、道具、服装的默认用途保存在项目资产记录。

## 项目资产与镜头

人物库中的“项目资产与镜头”提供人物、场景、道具、服装分类；现有人物身份从人物库读取，不复制人设。主体下登记造型／状态，可以关联服装和道具。每个具体素材记录路径、素材 ID、文件指纹、用途、阶段、候选／确认／停用状态及制作信息。不同视角按用途区分。

关系保存在项目的 `人物库索引/项目资产与引用.md` 的 `assetframe-production:v1` 区块。区块外原文保留；修改前检查指纹并建立旁边备份。未知版本、身份冲突或损坏不会被空记录替代。

镜头登记集数、场次、名称及可选分镜 MD。选用固定具体素材 ID 与 SHA-256，保存在现有素材库 `links` 中；分镜来源及指纹一同记录。新默认不改旧引用。反查勾选镜头后可明确更新版本，每次替换保留旧素材 ID、指纹、造型与时间。分镜来源变化需重新核对。

“导出本项目已选用素材”使用现有完整原文件交付，逐条核验绑定指纹；不选择其他高清版本、不裁切媒体。清单包含具体主体、造型、镜头、来源、提示词和复用模板。可复制制作交接，供 Codex、LibTV 或剪映人工继续使用。

## 给 Codex 的记录接口

1. 沿用项目和人物稳定 ID，改名不换身份。先读当前入口，不按最大版本号裁定当前稿。
2. 标准人物档案继续使用 `assetframe-character:v1`；具体确认使用 `assetframe-confirmation:v1`，字段见本目录“字段规范.md”。
3. 记录实际结果路径、真实 SHA-256、实际发送的原始提示词及已知平台／模型／参考素材。缺失项留空。
4. 只有用户明确确认具体结果，才写确认依据；AI 推测、评分、文件名和规划均不构成确认。
5. 新的项目资产关系使用 `assetframe-production:v1`，结构以 `ProjectAssetGraph` 的 Codable 类型为准。人物身份仅引用已有档案 ID，其他主体保存在 subjects；variants 记录状态组合，assets 记录素材版本，shots 记录镜头入口，events 追加制作与状态事件。
6. 外部修改先核对来源指纹并保留备份，未知正文保留。软件不会监听聊天、自动操作平台、生成媒体或修改全局 Skill。

本规范不改变本次创作任务的授权范围。候选 App 不代表正式安装或用户验收。
