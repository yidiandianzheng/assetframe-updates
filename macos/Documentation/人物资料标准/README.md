# 人物资料与资产确认标准 v1

适用：向量 AI资产管家标准人物记录 v1；新增资料整合入口见 V261017.2 隔离候选。各生成工具可共用本约定，不要求在某个平台内生成。

新增[漫剧工作流衔接](漫剧工作流衔接.md)：项目概览、标准记录直读、增量候选缓存、造型与项目资产、固定镜头引用及制作交接。具体构建与安装状态以软件交付记录为准。

## 每次生成与确认

1. 生成结果先是候选。保留原文件、实际使用的完整提示词、平台/模型和参考资产；不知道的内容标“待补充”，不补猜。
2. 用户确认具体文件后，可由 Codex 直接留下有效标准确认记录；刷新后软件核验并继承。也可在人物库选中人物，点击「记录资产确认」。选中该素材，填写造型、用途、适用阶段与确认依据，预览后保存。生成文件尚未进入素材库时，先使用现有导入入口。
3. 软件把 `项目 ID + 人物 ID + 具体文件 SHA-256` 与本次确认串联；写一份不可静默覆盖的确认记录，同时关联人物档案和模块索引。确认主图不自动确认声线，评分不代表确认。
4. 新图需要重新确认；原记录保留为历史事实。当前调用状态和默认用途在人物档案中维护，旧记录不自动覆盖已停用状态。文件改动后原指纹不再适用。

## 模块与唯一正文

| 模块 | 职责 | 存储 |
|---|---|---|
| 项目人物索引 | 稳定身份、资料类型、来源路径、读取指纹 | 项目根目录 `人物库索引/索引.md` |
| 人物档案 | 人设、性格、说话特点、关系、当前素材用途 | 已关联的标准人物 MD；新建时放入 `人物库索引/人物-摘要.md` |
| 资产确认与生成记录 | 某次确认的具体文件、原始生成提示词、可复用模板、确认依据 | `人物库索引/确认记录-摘要.md` |
| 既有介绍/说明书/提示词 | 历史与来源正文 | 保留原位置，通过索引和人物档案链接 |
| 软件检索登记 | 项目路径和人物 MD 路径 | 资源库 `character-library.json`，不另存人设正文 |

文件名里的摘要仅用于避免重名；不会用文件名或最大版本号裁定当前稿。索引可携带到另一资源库，登记项目时沿用其项目 ID；已有标准人物 MD 使用「关联人物 MD」恢复。跨项目同名人物仍独立。

## 提示词统一栏目

- **实际生成原始提示词**：保存真实发给生成工具的完整文本与参数，禁止用后续润色版本冒充。
- **固定特征**：已锁定的身份、脸、发型、体态等；无依据不补写。
- **可变部分**：本次允许调整的服装、阶段、动作、机位等。
- **禁改项**：本次必须保持的条件。
- **图片提示词 / 视频提示词 / 声音提示词**：按用途分开，不把图片描述冒充声音提示词。
- **参考资产说明**：实际参考素材、路径、对应用途。

标准化只调整字段归类与表达结构，不改变用户确认的设计；AI 产生的整理文字为候选。整理模板与原始生成提示词分别保留。

统一用词：人设确认、视觉确认、声线确认；当前资产状态使用「候选 / 已确认 / 历史停用」；人物字段状态使用「待补充 / 候选 / 已确认」；默认用途单独维护。主图、高清图、补图、身形参考、表情、声线分别关联。

## 链接项目文件夹后的流程

「登记项目」→本地读取标准记录→「项目资料整理」查看概览→选择工作流人物→必要时批次整理旧资料→集中预览保存。后续通过刷新发现新增、变化和问题。

本地扫描支持 UTF-8 Markdown，普通枚举跳过隐藏目录、历史/停用/备份/归档目录和符号链接目录；项目内明确 MD 链接可读取历史来源且保留历史属性；读取上限 30,000 个目录项、800 份相关文件、24 MiB 文字，单文件 256 KiB。不可读、截断和超限均提示，不算全项目识别完成。AI 每批最多 30 份、160 KB，仅发送用户勾选文字。

普通说明书的媒体链接先关联为候选，不凭“已确认”文件名改状态。标准确认记录会检查项目、人物、资产内容指纹；未入素材库的文件只保留链接并提示。多个来源同字段不同，或旧名与当前名不同，保留现有值、提示核对。项目扫描不自动修改旧说明书，也不自动读取或发送生成工具的聊天记录。

## 提供给生成工具的记录要求

> 本次生成后保留每一张实际候选、实际生成提示词、模型信息和参考资产。只有用户明确确认某个具体结果，才记录确认。记录所属项目和稳定人物 ID、文件路径、用途、适用阶段、确认依据及原始提示词；不要将计划、文件名“已确认”、评分或当前最大的版本号当成确认。已有角色改名保留原 ID。生成后可将信息交给人物库的“记录资产确认”表单，软件计算真实文件指纹并建立索引。

如由外部工具直接写标准记录，必须遵循 [字段规范](字段规范.md)，先核对真实文件 SHA-256 和用户确认依据。将生成结果留在自己的项目目录，不复制人设正文到多个平行档案。

## 保存失败与恢复

档案和索引写入前核对读取指纹，成功写回前备份到旁边 `.assetframe-character-backups/`。发现外部编辑停止写入，保留当前草稿；重新读取核对后再保存。

多文件保存不是跨文件数据库事务。若确认文件或档案已写出、后续登记/索引失败，界面会明确显示保留路径，可用「关联人物 MD」或项目扫描恢复，不会把部分成功显示为全部完成。确认记录不能原地改写为另一资产，补充/纠错应保留旧事实并重新登记。
