# 模块标准字段 v1

这是数据交换规范。使用 UTF-8 MD，JSON 位于各自唯一的标记区；生成模板不能含重复标记。未知字符串留空，不能伪造依据或哈希。下面是结构说明，不是已确认的真实记录。

项目索引的标记为 `<!-- assetframe-project-index:v1 -->` 与 `<!-- /assetframe-project-index -->`，其间有一个 json 代码块：

```json
{"version":1,"projectID":"稳定项目ID","references":[{"characterID":"P-01","kind":"人物档案","path":"相对于项目根的档案.md","fingerprint":"此来源文件实际SHA-256"}]}
```

索引只保存引用。kind 可用人物档案、资产说明、生成提示词、确认记录、项目入口、其他。

确认记录的标记为 `<!-- assetframe-confirmation:v1 -->` 与 `<!-- /assetframe-confirmation -->`，其间有一个 json 代码块：

```json
{
  "version":1,
  "id":"本次记录的UUID",
  "projectID":"稳定项目ID",
  "characterID":"P-01",
  "assetPath":"人物资产/具体文件.png",
  "sha256":"必须由实际文件计算的64位十六进制SHA-256",
  "materialID":null,
  "variant":"开局猎户装",
  "role":"主图",
  "stage":"开局",
  "status":"已确认",
  "confirmationEvidence":"实际用户确认依据或可追溯位置",
  "confirmedAt":"实际确认时间的ISO8601格式",
  "platform":"实际生成平台",
  "model":"",
  "originalPrompt":"实际用于此次生成的完整提示词；未知留空",
  "normalizedPrompt":{"固定特征":"","可变部分":"","禁改项":"","图片提示词":"","视频提示词":"","声音提示词":"","参考资产说明":""},
  "profilePath":"人物/唯一档案.md",
  "sourcePaths":["提示词/原始记录.md","人物/性格来源.md"]
}
```

role 仅接受：主图、高清图、补图、身形参考、表情、声线。status 接受：候选、已确认、历史停用。字段必须齐全（materialID 可省略或 null），真实确认记录需有实际依据与资产指纹。软件核验身份和内容一致性，不等于验证记录作者身份或核实用户对话真伪；外部数据仍需人核对。

人物档案继续沿用已有 `assetframe-character:v1` 格式：人物文本仅保存在标准 MD 正文；状态与引用元数据使用该格式。无需为本次模块索引迁移旧版人物文件。


## 项目资产记录 `assetframe-production:v1`（V261017.2 候选）

完整 Swift 类型为 `ProjectAssetGraph`，与人物 `assetframe-character:v1` 并存。人物正文和默认用途仍以原人物 MD 为准；项目资产关系不复制人设。

顶层必填：`version: 1`、`projectID`、`subjects`、`variants`、`assets`、`shots`、`events`。空数组应明确写 `[]`。每类对象的 `id` 唯一且稳定；不以名称作为键。标准块标记为 `<!-- assetframe-production:v1 -->` / `<!-- /assetframe-production -->`，块内是 JSON 代码块。请使用软件的“复制候选记录”取得完整结构，再按任务授权更新。

- `subjects`：`id/kind/name/description/sourcePath`，kind 只接受场景、道具、服装；人物直接引用已有标准档案的 characterID。
- `variants`：`id/subjectID/name/stage/fixedFeatures/costumeIDs/propIDs`。服装和道具引用对应 subjects ID。
- `assets`：`id/subjectID/variantID/materialID/path/sha256/role/stage/status/isDefault/evidence/originalPrompt/reuseTemplate/platform/model/referencePaths/createdAt`。实际文件 SHA-256 必须真实计算。候选不填写虚构确认依据；已确认必须有 evidence。人物默认用途保存在原人物 MD，图谱 isDefault 对人物应保留 false。
- `shots`：`id/episode/scene/name/sourcePath/sourceFingerprint`。来源可空；有来源时保存读取时的真实内容指纹。登记不代表已经生成或剪辑。
- `events`：`id/assetID/action/evidence/date`，追加更正或状态事件，保留原事件。

日期字段 `createdAt/date` 沿用当前 Codable 的数值编码：自 2001-01-01 00:00:00 UTC 起的秒数（可有小数）。确认记录 v1 的 `confirmedAt` 仍采用 ISO 8601 字符串，两者不要混用。路径可相对于项目根目录，跨项目素材允许绝对路径；镜头固定引用实际入库素材 ID 及指纹。不要将复用模板写入 originalPrompt，也不要将技术 QA 或剧情变化混入视觉确认。

软件会阻止身份、默认用途或文件冲突；文件未入库时，先使用“索引已确认文件”或人物详情的原位索引入口。原文件不被复制或移动。此标准不授权自动操作外部生成平台。
