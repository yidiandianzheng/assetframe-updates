# 分类规则

规则全部基于**文件名 + 目录名 + 产品名称映射表**，不做图像识别、不调用模型。每条结果都带 `evidence`，说明这一维是从文件名、目录名还是产品线推出来的。

## 0. 先划范围（scope）

| 判定顺序 | 条件 | scope |
| --- | --- | --- |
| 1 | 路径含 `/04_产品/` | 产品图 |
| 2 | 路径含 `/01_人物/` | 人物图 |
| 3 | 路径含「分镜」或 `/09_` | 分镜图 |
| 4 | 路径含「场景资产」或 `/03_场景` | 场景图 |
| 5 | 路径含 Logo / VIS / 视觉手册 | 品牌资产 |
| 6 | 图类型判为 PPT页面 | 文档页面 |
| 7 | 其余 | 其他素材 |

只有「产品图」参与品牌与茶类判定；其他范围的 `brand` / `tea_type` / `shot` 一律记「不适用」。这样产品覆盖率统计不会被 2000 多张非产品图拉低，也不会出现「文档页面品牌未识别」这种噪音。

## 1. 品牌

优先级：**文件名 > 产品线映射 > 目录名**。

1. 文件名（`name` + `originalFilename`）里命中任一品牌别名 → 取该品牌，`evidence=文件名`。
2. 否则若命中产品线且该产品线在映射表里登记了 `brand` → 取之，`evidence=产品线「…」`。
3. 否则目录段里命中品牌别名 → 取之，`evidence=目录名`。
4. 都没有 → `未识别`（不是「失败」，是命名里确实没有品牌线索）。

**关键排除项**：`project_root_names` 里的段（`中茶木兰姐`、`木兰姐`、`01_公共资产库`、`Codex工作区` 等）不参与品牌判定。这些是项目/库容器名，出现在每条路径里；若不排除，「中茶木兰姐」会让全库 7762 条都命中「中茶」。

同一层里出现多个不同品牌 → 记入 `conflicts`，按映射表顺序取第一个，留待人工裁决。

## 2. 茶类

优先级：**文件名 > 目录名 > 产品线映射**。

- 词表见 `产品名称映射表.json` 的 `tea_types[].terms`，含简体/繁体与品种名（铁观音、大红袍、东方奇种 → 乌龙茶；正山小种、金骏眉、海南红 → 红茶）。
- 文件名与目录名都没命中、但产品线登记了 `tea_type` → 用产品线的。
- 仍没有 → `未分类`。
- 若文件名/目录判出的茶类与产品线登记值不一致 → 记 `conflicts`，保留文件名结论（更贴近具体素材）。

## 3. 产品线

用映射表 `product_lines[].patterns` 匹配「文件名 + 目录」全文，**长模式优先**（避免「大红袍金罐」被更短的「大红袍」类模式抢走）。命中即取该产品线的 `name`；没有命中记 `未归类`。

新增产品线的做法：往 `product_lines` 里加一条，填 `patterns`（目录或文件名里的稳定片段）、`brand`、`tea_type`，重跑即可。

## 4. 机位（shot）

按映射表 `shots` 数组顺序匹配，**长词在前**：

```
高机位斜侧面 → 斜侧面 → 正面 → 侧面 → 背面 → 顶部俯视 → 底部 → 近景特写 → 全景
```

这个顺序保证「05_高机位斜侧面」不会被判成「侧面」，「07_顶部俯视」不会判成「俯视」。文件名优先于目录名；都没有 → `未标注`。

## 5. 图类型 / 用途

按 `asset_kinds` / `usages` 的关键词表匹配，数组顺序即优先级（透明素材 > 字体字样 > 对比图 > 平面设计稿 > 包装设计稿 > 视频抽帧 > PPT页面 > AI生成图 > 实拍照片）。用途无命中时默认 `设计素材`。

**2026-11-03 修掉的跨树误判**：目录关键词匹配用的是「去掉文件名后的全部上级」，所以卷级／客户级目录里的字会对整棵树生效。`04-客户与拍摄` 含「拍摄」，曾把其下 AI 生成图判成「实拍照片」（App 装机版里 144 张「实拍照片」有 88 张属此类）。修法与「中茶木兰姐会让整库命中中茶」是同一条机制：`04-客户与拍摄` 加入 `project_root_names`（Swift 侧 `GalleryAutoClassifier.projectRootNames`，本脚本侧 `产品名称映射表.json` 同步，映射表升到 1.1）。同时图类型补 **AI生成图**（词表 0.5）：别名含 `AI资产`／`ai视频`／`文生图`／`图生图`／`2k修复`／`4k修复`／`高清修复`／`即梦`／`豆包`／`ChatGPT`／`Codex 图像`。库里已经写下的旧误判由「按命名补全」纠正：只有新规则给出**不同且非空**的值才替换（登记在 `correctableTerms`），无命中保持原值，绝不清空。

**已执行（V261023.9，2026-11-03）**：装机后 `assetframe-cli backfill` 返回 `updated: 79`、`canUndo: true`（纠正旧误判 68 ＋ 补空值 11）。回读 2904 张图片：`实拍照片 144 → 76`（新规则命中 56 ＋ 无命中按设计保持原值 20）、`AI生成图 79`（新规则命中 85，其中 6 张库里已有更具体值 视频抽帧 5／包装设计稿 1 未被覆盖），`资产类型 1658` 不受影响。本目录离线引擎重跑后 产品图 475、`筛选核验.json` 的 `consistent=True`；脚本侧计数为 AI生成图 107／实拍照片 17，与 App 侧不同属既有差异（本脚本把文件名与全部上级拼成一段文本单趟匹配、且无命中默认记 `图片素材`，Swift 侧是文件名优先、目录次之、无命中留空），两边规则语言（排除名单与优先级表）已一致。

## 6. 比例

优先用素材的 `mediaMetadata.pixelWidth/pixelHeight` 求最简比，容差 ±2%；SVG 直接记 `矢量`；无尺寸信息记 `未知`。

## 7. 验收（acceptance）

| 路径特征 | 取值 |
| --- | --- |
| 含 `01_已确认` / `已确认` | 已确认 |
| 含 `02_待确认` / `待确认` | 待确认 |
| 其他 | 待核 |

「待核」是默认态，对应截图里的「来源：验收状态待核」——意思是路径里没有验收结论，需要人工确认，而不是判它不合格。

## 8. 整理状态（organize_status）

| 条件 | 取值 |
| --- | --- |
| 非产品图 | 不适用 |
| 验收=已确认 且 品牌、茶类都已识别 | 可用 |
| 验收=已确认 但品牌或茶类缺失 | 待补标签 |
| 其余 | 待整理 |

「可用」是唯一可以进正式营销引用的状态；「待补标签」表示内容已验收、只是命名缺线索，优先补映射表；「待整理」表示还没验收。

## 9. 一致性校验

每次运行都会输出 `输出/筛选核验.json`，检查每个维度的取值计数之和是否等于图片总数。任何维度不等，说明分类过程丢了记录，必须先修引擎再谈筛选结果。

## 10. 资产类型（asset_type）

回答「这张图是哪类资产」，与「图类型」（同一张图的呈现形式：PPT 页面／包装设计稿／对比图…）和品牌（归属主体）是三件事，不重复建维度。取值 16 个：人物角色、场景、道具、分镜、参考图、服装、色卡、产品、封面海报、包装、特效、示意层、品牌标识、VI规范、文字资产、其他资产。

判定顺序：**目录约定 > 文件名关键词**。目录约定是既有习惯，命中即定，不再看文件名：

| 目录特征 | 取值 |
| --- | --- |
| `01_人物`／`人物资产`／`角色资产` | 人物角色 |
| `03_场景`／`场景资产` | 场景 |
| `05_道具`／`道具资产`／`茶杯资产`／`茶叶资产` | 道具 |
| `02_分镜`／`09_分镜`／`分镜图`／`抽帧`／`宫格` | 分镜 |
| `07_风格`／`资料与参考`／`证据` | 参考图 |
| `08_色卡` | 色卡 |
| `06_文字资产`／`上屏PNG` | 文字资产 |
| `04_产品` | 产品 |
| `VIS手册`／`VI视觉规范`／`VI系统`／`规范图`／`规范总览` | VI规范 |
| `主Logo`／`Logo` | 品牌标识 |
| `14_其他资产` | 其他资产 |

VI 与 Logo 排在内容词之前，否则「2026-11-02_VI视觉规范与组合系统」这种同时带 Logo 字样的目录会被误判；`04_产品` 在 Logo 之前，保证「海南红茶_引流款_小Logo_候选」这类包装稿仍算产品资产。文件名兜底按 词表别名 走同一优先级：VI规范 > 品牌标识 > 文字资产 > 人物角色 > 场景 > 道具 > 分镜 > 色卡 > 服装 > 封面海报 > 包装 > 产品 > 参考图 > 特效 > 示意层 > 其他资产。

**允许留空**：PPT 工程目录（`review`／`svg_output`／`sources/*_files`）与详情页过程稿没有资产类型语义，不写值，交给「图类型」维度表达。香万家木兰库实测 2904 张图片命中 1658（目录 1503／文件名 155），留空 1246 张属正常。

## 11. 命名约定

库里已经有一套在用的好命名，规则从它归纳，不另立标准：

```
类型NN_品牌或对象_视角或用途_比例_vNN_状态.ext
色卡01_木兰姐高级泡茶高调母色卡_已确认.png
产品01_岁三窖陶罐_已确认.png
场景04_真实主茶空间_已确认.png
Logo02_香萬家_主标志_4500px_已确认.png
木兰姐_古今铜镜_抖音封面_3x4_v04.png
```

要点：类型前缀带两位序号（`人物01`／`场景03`），品牌或对象紧随，视角／用途再后，版本用 `vNN`，状态用 `已确认／待确认／候选／备用`。分隔符统一下划线，不用空格、不用中文顿号。

需要改名的图片当前 260 张（占图片总数 9%），来源是生图工具默认名（`ChatGPT Image 2026年8月16日 22_21_34 (2).png`）、微信转发名（`微信图片_20260812155705_112_62.png`）、随机哈希名（`2k修复_00001_nxetn_1786541281.png`）和纯编号（`IMG_9227.JPG`）。逐张建议名见 `../交接记录/资产类型与命名_2026-11-03/改名预览_命名不可读图片.csv`；**规则引擎不改文件**，改名需要人工确认后再执行，因为素材的 `sourcePath` 一旦变化，已建立的来源关联与项目索引都要同步。
